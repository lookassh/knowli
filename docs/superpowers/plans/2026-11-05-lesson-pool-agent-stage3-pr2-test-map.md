## 0. Wnioski przekrojowe (ważne dla planu)

1. **`tests/integration/fakes.ts` dziś NIE składa agenta**: `fakeGeneration()` zwraca `deps: { llm, tts, image, mediaStore }` bez `lessonAgent`, więc KAŻDY `executeLessonGeneration` w `lesson-generation`, `lesson-chapter` i plikach pomocniczych idzie potokiem przez `FakeLlmProvider.generateLessonPool`. Po PR 2 `fakeGeneration()` musi dołożyć `lessonAgent` (fake-agent + `FakeExerciseChecker({unavailable:true})`) i wystawić uchwyt (`fakes.agent`) do asercji w miejsce `fakes.llm.lessonRequests`.
2. **`lesson-agent-generation.test.ts` zależy od metody, która znika**: `agentWorld` tworzy `new FakeLessonPoolAgent({ fromLlm: fakes.llm, ... })`, a ~25 testów używa kroku `llmStep(fakes.llm)` (= `{fromLlm}`) i wrapperów `oneFamily` (l.1150), `addGenerator` (l.1353), `openPool` (l.1753) opartych o `llm.generateLessonPool({...input, existingExercises: <tablica długości offset>, stageCounts})`. `existingExercises`/`purpose`/`existingAnswers` znikają z `LessonPoolInput` (§3), więc „offset” trzeba przeliczyć na wejście podagenta (§5.2 pkt 2: liczba istniejących ćwiczeń zagadnienia / `avoidSentences` / `cardSentences`). Cały plik wymaga adaptacji (nie tylko usunięcia testów „potok”).
3. **Agent nie zapisuje `rejectedReasons`**: `lesson-agent-generation.ts` l.304 i l.357 ustawiają `rejectedReasons: {}`; `rejectedCount` = usunięcia po przyjęciu (`removedAfterAcceptance + check.removed`), nie odrzucenia w pętli (test agentowy l.750). Wszystkie asercje potoku na `draft.rejectedReasons` (`"słowo spoza materiału: umbrella"`, `EXPOSURE_REASON`…) i `rejectedCount > 0` po wadliwym wejściu NIE przenoszą się 1:1; powody odrzuceń żyją w `agent_checkpoint.rejectionCodes` (podsumowanie) i w logach `[lesson-agent]`. §6.1 „pełne odrzucenie daje failed/validation **z powodami**” wymaga decyzji: albo asercja na `rejectionCodes`, albo agent ma zacząć zapisywać `rejectedReasons` (zmiana domeny, nie samego testu).
4. **`historyLikeSubject` nie ma `agentPolicy`** (`testing/history-like-subject.ts`), a §4.3 robi je obowiązkowym → testy `test_history` (l.1049, 1077 + `child-interests.test.ts:175-180`) potrzebują `withAgentPolicy(historyLikeSubject)` z `packages/server/src/domain/lessons/testing/agent-test-subject.ts` (nieeksportowany z `@learning/server`; testy importują go względną ścieżką, jak `fake-lesson-agent`).
5. Agent uruchamia zagadnienia **równolegle** (`maxConcurrent`), więc testy zależne od kolejności partii pipeline'u (druga partia widzi rozwiązania pierwszej; „numeracja bez kolizji”) nie mają odpowiednika — zostaje deterministyczne źródło ujawnień: `cardSentences`, przykłady z planu (`plans` w opcjach fake-agenta), `fixed`.
6. Planista fake'a rozdziału daje ≥3 zagadnienia z pokrycia (`fakePlanFromCoverage`: `["words","words","frame"]`, id `part_1..3`); testy rozdziału zakładające `["words","frame","frame"]` i tytuły „Zagadnienie N: …” zmieniają oczekiwania (lesson-chapter.test.ts l.121, 124, 712, 723, 726).
7. Logi potoku `[lesson] walidacja puli:`, `błąd partii LLM`, `ujawnienia: usunięte=`, `sanityzacja wariantów:`, `porzucone wyjaśnienia=`, `dogenerowanie pod etap:` znikają. Zostaje wspólny log `[lesson] run=… zakończony: state=… kod=…` (z `markLessonRun`, l.1577 `lesson-drafts.ts`) oraz `[lesson-agent] …` (unit: `lesson-pool-agent.test.ts:202`).
